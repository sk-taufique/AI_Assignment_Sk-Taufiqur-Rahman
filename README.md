## 1. Project Overview
A small machine-learning system that reads the **description of a customer support ticket** and
automatically predicts its **category** (Login Issue, Application Error, Report, Account Update, Performance).
It also shows a **confidence score** and a **suggested customer reply** (optional bonus task).

## 2. Problem Statement
Support teams receive hundreds of tickets by email/chat. Sorting them by hand is slow.
The goal is to learn from past tickets and route a new ticket to the right category automatically.

```
Ticket Description -> Text Cleaning -> TF-IDF -> Logistic Regression -> Predicted Category (+ confidence)
```

## 3. Technologies Used
Python 3.x · Pandas · NumPy · Matplotlib · Seaborn · Scikit-learn · Joblib · Flask (HTML/CSS for the web page).
No other third-party libraries and **no external AI API / API keys** are used.

## 4. Dataset Information
- **Self-created (synthetic) dataset** – no external dataset was downloaded.
- Generated by `src/generate_dataset.py` from hand-written ticket sentences + natural variations (greetings, "please help", etc.)
  plus a set of harder/ambiguous tickets (e.g. "Report page shows an error"). Priority and status are random, because
  the model only uses the description.
- 280 raw rows → **270 rows after cleaning**, **5 categories**: Login Issue, Application Error, Report, Account Update, Performance.
- Fields: `ticket_id, customer_name, ticket_description, date, priority, status, category`.
- Dirty data (5 duplicates, 3 missing values) was added on purpose to demonstrate the cleaning step.

## 10. Limitations (short)
Small, synthetic dataset; wording is more regular than real customer emails; overlapping words (e.g. "slow" + "error")
cause confusion; unknown topics are always forced into one of the 5 categories. See `report.pdf` for details.

## 11.Conclusion
This project built a working system that predicts the category of a customer support ticket from its description. The ticket text is cleaned, converted into TF-IDF features and classified by a Logistic Regression model. On 54 unseen test tickets the model reached 94.4% accuracy (precision 95.2%, recall 94.4%, F1 94.4%), and it predicted all 8 completely new tickets correctly. The few mistakes happened where categories share words, such as “slow” and “error”.

The solution is simple, fast and explainable, and it also shows a confidence score so uncertain tickets can be reviewed by a person. Its main limits are the small synthetic dataset and the fixed set of 5 categories, so real-world accuracy would probably be lower. With more real tickets, better text processing and a stronger model, the same approach could help a support team sort tickets automatically and respond faster.
